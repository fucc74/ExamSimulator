# ExamSimulator

An exam-agnostic practice engine that runs as a **single HTML file** (works by double-clicking `exam.html`, no server needed).
Add as many exams as you like: each exam is one `NAME.exam` file.

## Using it
- Open `exam.html`, pick an exam from the list (or open `exam.html?content=NAME`, or `exam.html?url=https://…/NAME.exam`).
- **Modes:** exam-defined modes (e.g. official simulation), full bank, per topic, spaced-repetition review, my mistakes, flagged, unseen, by difficulty.
- **Study mode** (check each answer + explanation) or **exam mode** (change answers freely, review screen before submitting).
- **Timers:** total, per question, or none.
- **Flag & notes** per question; statistics (history, accuracy by topic, hardest questions); export/import of all progress.
- **Keyboard:** `1–6`/`A–F` select, `←/→` move, `Enter` check/next, `M` flag, `X` clear, `R` report, `P` pause, `Ctrl/⌘+K` command palette, `/` search, `?` help.
- **Exam realism:** optional partial credit and negative marking, mandatory questions, limited pauses, strict clock, pace indicator, printable result. You can always move freely between questions.
- **Search** the whole question bank (text, topic, type, difficulty, status) and practice exactly the results.
- **My exams:** import a `.exam`, CSV, Markdown or plain text file with a guided wizard, fix problems in the built-in editor (images, code, formulas supported), save in the browser, export as `.exam`, CSV, Markdown or Anki.
- **Options page** (gear icon): scoring defaults, exam rules, profiles, backup and reminder, sync, storage, library, question reports.
- **Your data:** several profiles on one device, IndexedDB storage, backup reminder, automatic backup to a file you choose (Chromium browsers), transfer code to move progress between devices, optional private GitHub Gist sync.
- **Exam versions:** a changelog shown when an exam is updated, revised questions return in review, retired questions are never asked; wrong-question reports; automatic quality hints (too easy/hard, suspicious answer key, weak distractors).
- **Updates:** the app tells you when a new version is available instead of switching silently.
- Responsive design for phone, tablet and desktop (bottom action bar and collapsible progress grid on phones), English/Italian UI toggle, light/dark theme, installable and usable offline (when served over http/https).

## Adding an exam
1. Create `NAME.exam` (format 2 — see [docs/EXAM-FORMAT.md](docs/EXAM-FORMAT.md)).
2. `node tools/validate-exam.js NAME.exam` — readable errors and quality hints.
3. `npm run build` — regenerates the exam list, `exam.html` and the offline cache list.

Old-style exam files (`window.ExamData = {config, questions}`) still load; convert them with `node tools/convert-legacy.js`.

## Development
```
src/            sources (styles, js modules, template)
tools/          build.js, make-manifest.js, validate-exam.js, convert-legacy.js
tests/          unit tests (node:test) and browser end-to-end tests (Playwright)
exam.html       GENERATED single-file build — do not edit by hand
exams.js, sw.js GENERATED by `npm run build`
```
- `npm run build` — bundle `src/` into `exam.html`
- `npm test` — unit tests (no dependencies)
- `npm run e2e` — browser tests (`npm ci` then `npx playwright install chromium`); `E2E_BROWSER=firefox|webkit`, `E2E_DEVICE="Pixel 7"`, `E2E_ONLY=name,name` narrow the run
- `npm run audit` — accessibility (axe-core, light and dark) and performance budget; `npm run visual` — screenshot comparison (`visual:update` regenerates the baseline)
- `npm run pack` — static site in `dist/` for any host

### Continuous integration and publishing
`.github/workflows/ci.yml` runs on every push and pull request: build is up to date, unit tests, exam validation, end-to-end tests on Chromium, Firefox and WebKit, mobile emulation (Pixel 7, iPhone 14), accessibility/performance audit and visual regression.
`.github/workflows/pages.yml` publishes the site to **GitHub Pages**: in the repository go to *Settings → Pages → Build and deployment → Source: GitHub Actions* once, then every push to `main` deploys to `https://<user>.github.io/<repo>/`.
Visual regression needs a baseline made on the machine that checks it: run the CI workflow manually with *update_visual_baseline* ticked, download the `visual-regression` artifact and commit `tests/visual-baseline/`.

Extension points are described in [docs/API.md](docs/API.md) (events, custom question types and modes).
